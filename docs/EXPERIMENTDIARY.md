# Дневник экспериментов

Хронология работы: что запускалось, что сломалось, какие числа получились. Тупики
и отрицательные результаты приведены наравне с удачными прогонами — они заняли
существенную часть времени и объясняют, почему итоговый пайплайн выглядит именно так.

Обозначения: п.п. — процентные пункты, ДИ — доверительный интервал (95%,
бутстрап), p — точный тест Макнемара.

## Этап 0. Окружение

**Задача:** запустить QLoRA-обучение LLaVA-модели в бесплатном Colab на T4.

Три блокирующие проблемы, каждая потребовала отдельной диагностики:

| Проблема | Симптом | Решение |
|---|---|---|
| Pillow 12.0+ | `ImportError: cannot import name '_Ink' from 'PIL._typing'` на `import peft` | `pillow<12,>=10.0.0` + принудительный перезапуск ядра, если несовместимая версия уже в памяти |
| transformers v5 | `lm_head` теряет `quant_state` при 4-bit + `device_map="auto"` | `transformers>=4.46,<5` |
| Устаревший `processor_config.json` | `LlavaProcessor` падает на делении: нет `patch_size` | проставлять `patch_size`, `vision_feature_select_strategy`, `num_additional_image_tokens` вручную из `model.config` |

**Итоговое окружение:** transformers 4.57.6, peft 0.19.1, torch 2.11.0+cu128,
datasets 5.0.0, accelerate 1.14.0, Tesla T4 14.6 ГБ.

## Этап 1. Подготовка данных

**Тупик: токенизация промпта голым `tokenizer`.**

Первая версия сборки примера вычисляла длину промпта через `tokenizer`, а весь пример —
через `processor`. Ошибка:

```
Image features and image tokens do not match: tokens 1, features 576
```

Причина: `tokenizer` оставляет `<image>` одним токеном, `processor` разворачивает его
в 576. Решение — считать длину промпта тем же `processor`, что и весь пример. Побочный
эффект: изображение препроцессится дважды на каждый пример, что заметно замедляет
обучение. Оптимизация не выполнялась (см. «Что не сделано»).

**Тупик: рекурсия в `__getitem__`.** При ошибке загрузки примера датасет рекурсивно
брал следующий, что при серии сбоев давало `RecursionError` и прятало настоящую причину.
Заменено на цикл из 20 попыток.

**Диагностика:** длина последовательности 600 токенов, доля токенов в функции потерь —
0.003 (около 2 токенов из 600). Зафиксировано как ожидаемое следствие однословных
ответов.

## Этап 2. Обучение (прогон 1)

**Конфигурация:** 4000 примеров, 1 эпоха, batch 2 × grad_accum 8 = 16, 250 шагов,
LR 2e-4 cosine, warmup 3%, LoRA r=16 α=32 dropout=0.05, 4-bit NF4, fp16,
gradient checkpointing.

**Результат:** 60.5 минут (≈14.5 с/шаг), 19 611 648 обучаемых параметров (0.69%).

| Шаг | Loss |
|---|---|
| 10 | 6.0164 |
| 20 | 0.7800 |
| 250 | 0.4913 |

Среднее по всем шагам — 0.8881.

**Наблюдение:** падение loss происходит за первые ~20 шагов, дальше плато. Это освоение
формата ответа, а не приобретение способностей. Записано как аргумент в пользу гипотезы
о «дообучении в потолок» — train-сплит `GQA-ru` базовая модель уже видела при instruction
tuning авторов.

## Этап 3. Оценка, версия 1 — некорректная

**Конфигурация:** по 200 примеров на бенчмарк, оценка сразу после `trainer.train()`.

| Бенчмарк | База | LoRA |
|---|---|---|
| GQA-ru, Exact Match | 0.000 | 0.005 |
| MMBench-ru, accuracy | 0.630 | 0.645 |

**Аномалия.** Опубликованное авторами значение для базовой модели на GQA-ru — 46.37.
Ноль невозможен для работающей модели, тем более в паре с разумными 63% на MMBench.

**Диагностика.** Предупреждение при генерации:

```
Caching is incompatible with gradient checkpointing in GemmaDecoderLayer.
Setting `past_key_values=None`.
```

Печатается только при `self.gradient_checkpointing and self.training` — значит модель
осталась в режиме `train()`. Дальше: KV-кэш отключён → `pixel_values` передаются только
на первом шаге генерации → со второго токена изображение исчезает из контекста.

**Подтверждение.** Сырые ответы: `металлметалметалметал…` вместо `металл`. Валиден только
первый токен — поэтому MMBench (одна буква) выжил, а GQA (целое слово) обнулился.

**Исправление:** `model.eval()`, `model.gradient_checkpointing_disable()`,
`model.config.use_cache = True`.

Ноутбук `01_train_lora.ipynb` с этими результатами оставлен в репозитории намеренно.

## Этап 4. Оценка, версия 2 — исправленная

**Изменения:** отдельный ноутбук `02_eval.ipynb`, загрузка адаптера с Google Drive,
`model.eval()` + три ассерта, батчевая генерация по 8 с левым паддингом, проба на 20
примерах со стоп-краном, бутстрап-ДИ и тест Макнемара, выборки увеличены до 1000.

**Скорость:** 0.56 с на пример, 4000 генераций за 37 минут.

Результат (режим промпта: `add_special_tokens=False`, то есть без `<bos>`):

| Бенчмарк | База | LoRA | Разница | p |
|---|---|---|---|---|
| GQA-ru | 35.4% [32.4; 38.5] | 37.9% [34.9; 40.9] | +2.5 п.п. [−0.1; +5.0] | 0.058 |
| MMBench-ru | 52.7% [49.6; 55.8] | 62.6% [59.6; 65.6] | +9.9 п.п. [+7.0; +12.8] | 1.5·10⁻¹⁰ |

Базовый уровень случайного угадывания на MMBench-ru — 26.65%.

**Проверка фикса:** GQA-ru у базовой модели 0.000 → 0.354. Первая ошибка устранена.

**Тревожный признак.** Контрольная генерация на стоп-знаке:

```
База:  Опиши картинку несколько словами.
LoRA:  На фотографии изображен красный стоп-знак, который находится на углу улицы.
```

Базовая модель воспроизвела инструкцию вместо ответа, причём с грамматической ошибкой —
то есть генерировала, а не копировала вход. Признак вырожденного режима.

**Диагностика токенизации:**

```
add_special_tokens=False -> ['<start_of_turn>', 'user', '\n', '<image>', '\n']  | <bos>: 0
add_special_tokens=True  -> ['<bos>', '<start_of_turn>', 'user', '\n', '<image>'] | <bos>: 1
```

Chat template чекпоинта не вставляет `<bos>`. Основной прогон выполнен вообще без него.
Адаптер обучался в этом режиме, базовая модель — нет. Возникло подозрение, что прирост
+9.9 п.п. отражает не качество модели, а формат промпта.

## Этап 5. Контрольный эксперимент: формат промпта

**Гипотеза:** прирост на MMBench-ru объясняется отсутствием `<bos>`, а не дообучением.

**Дизайн:** все четыре комбинации `модель × режим промпта` на одних и тех же 1000
примерах каждого бенчмарка. Результаты этапа 4 переиспользованы, досчитаны две
недостающие конфигурации.

**Время:** 20 минут.

**Таблица 2×2:**

| | GQA-ru, без BOS | GQA-ru, с BOS | MMBench-ru, без BOS | MMBench-ru, с BOS |
|---|---|---|---|---|
| База | 35.4% | 39.6% | 52.7% | 63.2% |
| LoRA | 37.9% | 39.2% | 62.6% | 64.3% |
| Эффект дообучения | +2.5 п.п. (p = 0.058) | −0.4 п.п. (p = 0.712) | +9.9 п.п. (p < 0.001) | +1.1 п.п. (p = 0.305) |

**Эффект формата промпта:**

| Модель, бенчмарк | Δ (с BOS − без BOS) | p |
|---|---|---|
| База, GQA-ru | +4.2 п.п. | 0.0083 |
| LoRA, GQA-ru | +1.3 п.п. | 0.2753 |
| База, MMBench-ru | +10.5 п.п. | < 0.0001 |
| LoRA, MMBench-ru | +1.7 п.п. | 0.0604 |

**Вывод: гипотеза подтверждена.** Прирост был артефактом формата. В корректном режиме
эффект дообучения статистически не отличим от нуля на обоих бенчмарках. Базовая модель
значимо зависит от `<bos>`, дообученная — нет.

**Побочный результат:** устойчивость к формату промпта — единственный статистически
подтверждённый эффект адаптера.

## Этап 6. Проверка стратегии выбора визуальных признаков

**Гипотеза:** чекпоинт обучался со стратегией `vision_feature_select_strategy = "full"`
(577 признаков CLIP, включая CLS-токен) вопреки значению `default` (576 патчей) в
конфиге; из-за этого теряется часть визуальной информации и не воспроизводятся
опубликованные 46.37.

**Дизайн:** только базовая модель (адаптер обучался с `default`, прогонять его с `full`
означало бы повторить ошибку этапа 5), GQA-ru, n = 200, промпт с BOS.

**Технический нюанс:** `num_additional_image_tokens` описывает выход визуального
энкодера (CLS = +1) и должен быть равен 1 в обоих режимах — ветка `default` внутри
процессора сама вычитает эту единицу. Установка 0 для `full` даёт несовпадение числа
токенов.

**Результат:**

| Стратегия | Exact Match |
|---|---|
| `default` | 39.00% |
| `full` | 36.00% |

Разница −3.00 п.п. [−7.50; +1.50], p = 0.2863.

**Вывод: гипотеза отклонена.** `full` не лучше; точечная оценка даже отрицательная.
Верхняя граница ДИ исключает выигрыш больше 1.5 п.п., то есть гипотеза не может
объяснить семипунктовый разрыв ни при каком исходе — увеличивать выборку не требуется.
Значение `default` согласуется с оригинальным LLaVA, где используется
`mm_vision_select_feature: patch`.

**Побочная проверка:** `default` на 200 примерах дал 39.00% против 39.60% на основной
выборке в 1000 примеров. Расхождение 0.6 п.п. при ожидаемом шуме ±6.8 п.п. — измерения
воспроизводимы.

## Этап 7. Качественная иллюстрация

**Задача:** показать эффект формата промпта наглядно.

**Дизайн:** три примера × четыре ответа (база / LoRA × без BOS / с BOS). Примеры из GQA
подбираются автоматически из расхождений между моделями — по одному в каждую сторону.

**Тупик в первой версии.** Примеры отбирались по маскам этапа 4, посчитанным при
`BATCH_SIZE = 8`, а качественная ячейка генерирует по одному примеру. Батчинг с левым
паддингом меняет численность матричных операций, и пограничные примеры дают другой ответ.
В результате пример, помеченный «база права, LoRA нет», при одиночной генерации показал
одинаковые ответы у обеих моделей — подпись противоречила содержимому.

**Исправление:** проверять до четырёх кандидатов и брать первый, где модели действительно
расходятся; подписи строить по фактически показанным ответам, а не по старым маскам.

**Методическое следствие:** отдельные примеры нестабильны, выводы строятся только на
агрегатах. Сравнение моделей внутри одного прогона при этом корректно — обе идут
с одинаковым батчингом.

## Что не сделано и почему

| Идея | Почему не сделано |
|---|---|
| Полные прогоны бенчмарков (12 216 + 3910) | ~32 000 генераций, ~7 часов — не помещается в бесплатную сессию Colab |
| Воспроизведение строгого протокола `lmms-eval` | сознательный отказ, а не нехватка времени: строгий разбор смешивает понимание изображения с соблюдением формата, а адаптер обучался именно на формате — оценка была бы завышена и неверно интерпретирована (обоснование — `REPORT.md`, раздел 6.2). |
| Обучение на полном train-сплите (40 000) | 2500 шагов ≈ 10 часов при текущей скорости — не помещается в бесплатную сессию Colab; потребовало бы разбиения на сессии с возобновлением от чекпоинта |
| Устранение двойного препроцессинга изображения | издержка чисто скоростная, на веса не влияет; исправление потребовало бы переобучения |
| Валидационный сплит и отбор чекпоинта | при 250 шагах и отсутствии признаков переобучения отбор чекпоинта дал бы мало, а валидация отняла бы часть и без того небольшой обучающей выборки |
| Количественная оценка эффекта Exact Match на синонимах | требует ручной разметки или отдельной модели-судьи |
